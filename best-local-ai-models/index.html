Quantization explained

It's the concept that makes local AI possible on normal PCs. If you understand it, you also understand why 0.4 GB and 40 GB files exist for the same model.

A model stores its "weights" in a numeric format chosen at release time. Quantizing reduces the memory used, but it can change quality differently depending on the model, the format, and the task. Actual sizes also vary between files of the same model.

Size and precision are different trade-offs

A larger model can achieve better results on some tasks, but it isn't a universal rule. Quantization can affect code, language, reasoning, and other tests differently. Compare specific versions on your use case instead of choosing only by parameters or bits.

Size drives memory and time

Generation repeatedly works over the weights and the context data, so larger models tend to need more memory and time. Real throughput depends on bandwidth, CPU/GPU, backend, quantization, and context length: it can't be inferred precisely from size alone.

Frequently asked questions

What is the best model for 8 GB of RAM?

With 8 GB total, free memory depends on the OS, applications, and context. Small or mid-sized quantized models are a starting point; some 7-8B models can be at the limit. The examples in the catalog are not an up-to-date ranking: verify the file, runtime, and requirements before downloading.

What's the difference between a 7B and a 14B?

The result varies with the model and the task: more parameters don't guarantee a better answer. A quantized 14B generally needs more memory than a 7B; also consider context, runtime, and operating system. Check the actual size and leave additional room.

What is Q4_K_M quantization and does it really matter?

Quantization reduces the memory used by the weights compared with higher precisions. Q4_K_M is a common trade-off, but the impact on quality varies by model and task; compare the specific variant. More compressed formats require less memory but can degrade some capabilities more.

Does a larger model always give better results?

No. Size, quality, and speed don't have a simple relationship: the result depends on the model, task, quantization, and hardware. More parameters often increase memory and time, but quality must be judged on your use case.

Which model speaks Italian best?

There is no universal winner: language, version, prompt, and task change the results. Qwen, Llama, Gemma, and other families have instruct variants that can reply in Italian; try the available versions with your own requests.

How do I free memory for a larger model?

Close unneeded applications, shorten the context, and choose a lighter quantization when available. A lightweight operating system can help, but it doesn't guarantee that a model will fit: consider cache, buffers, and real free memory.

Where do I download them?

From Hugging Face, which is the reference repository, or directly from LM Studio or with an Ollama command. The LM Studio configurator shows which format to download for your hardware; if you prefer the terminal and want to serve models to other programs, the guide is on the Ollama vs LM Studio page.

How to evaluate a local AI model

To compare models, consider the task, the quality you need, the size of the weights, and the system memory. The file on disk is only part of the requirement: context, cache, runtime, and open applications need additional space.

Quantization reduces the memory of the weights and can affect quality. The effect varies from model to model; try the exact version with requests similar to your work. The parameters and estimates on this page are indicative, not benchmarks.

A GPU can speed up inference if drivers, backend, and runtime support it. How much of the model can be assigned to VRAM also depends on context and buffers; speed can't be derived from the card's capacity alone.

Before downloading or distributing a model, verify source, version, format, requirements, and license of the specific variant.
