Memory depends on usage and settings

Consumption cannot be summarized in a single number: it changes with system, session and model. Even how long a model stays loaded depends on the settings. In Ollama you can check the active models with ollama ps and unload one with ollama stop nome-modello; for LM Studio, check the unload options in the installed version. The amount of free RAM on your PC is more useful than a generic measure of the application.

Step-by-step installation

Basic steps and links to the official documentation. Requirements and installation options can change by system and version.

LM Studio

  1. Download the version for your system from lmstudio.ai/download and check the published requirements.
  2. Install with the default settings. On first launch choose the "My Documents" mode only if the system disk is almost full: the models are large.
  3. Look for a model suited to your RAM and your use; the download size and the time depend on the variant and the connection.
  4. In the menu on the left open "Local Server" and press Start. LM Studio exposes a server compatible with the OpenAI APIs on localhost:1234: any program that accepts an OpenAI endpoint can use it.
  5. Start the model with a context suited to the available memory and check the RAM usage during a test.

Ollama

  1. Windows or macOS: download OllamaSetup.exe from ollama.com/download and install it. On Windows it becomes a background application with an icon in the status bar.
  2. Linux: a single command, which installs the binary and creates the system service: 
    curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable --now ollama
  3. Download and start a model with a command: 
    ollama run qwen2.5:7b
  4. For everyday use it is better to preload the model without starting it: ollama pull qwen2.5:7b. That way the next startup is immediate.
  5. List the installed models with ollama list and delete one you do not use with ollama rm nome-modello: every model takes gigabytes that do not come back.

Windows 7 is not supported

Operating system requirements change with versions. Check the official pages of LM Studio and Ollama before installing. On an old PC, Linux can be an alternative only if the distribution, the drivers and the runtime support that CPU model; RAM consumption depends on the configuration.

Using Ollama from other programs

This is the main reason people choose Ollama: a local model becomes usable from any program, even one written in any language, without an account or costs.

The minimal command

Ollama listens on port 11434 of the localhost address. The simplest request is made with curl:

curl http://localhost:11434/api/chat \
  -d '{
    "model": "qwen2.5:7b",
    "messages": [{"role": "user", "content": "Riassumi il teorema di Bayes in tre righe"}],
    "stream": false
  }'

With "stream": false you receive a single JSON block when the model has finished. With true, which is the default, you receive one piece of the response at a time, exactly like in a chat: for a web interface that is what you need.

OpenAI-compatible endpoints

Ollama also exposes a /v1 path compatible with some OpenAI APIs. Check the parameters supported by your program and do not expose the port to the Internet: limit access to the trusted local network or add an appropriate authentication layer.

Python example

With the official ollama library the request is three lines:

import ollama

risposta = ollama.chat(
    model="qwen2.5:7b",
    messages=[{"role": "user", "content": "Ciao, chi sei?"}]
)
print(risposta["message"]["content"])

Confirming it works

The quickest test to understand whether the service is running, with a command that works on Windows, Linux and macOS:

curl http://localhost:11434/api/tags

If it replies with a JSON that lists the models you downloaded, everything is in order. If you get a connection error, the service is not running: on Linux check with systemctl status ollama.

LM Studio does the same thing

LM Studio also has a local server: you activate it from the "Local Server" menu and it listens on port 1234, not 11434. The difference is that its server is designed for interactive use and must be started by hand at every session, while the Ollama server is a service that starts with the system. If a program asks you for the port, try 1234 with LM Studio and 11434 with Ollama.

One model, two PCs

In a home with more than one computer, the old PC is not there to run models: it is there to act as a server for the others. It is a use that works even on 2012 hardware.

Ollama is designed for this: just expose it on the local network and every PC in the house will be able to ask it for answers. The model runs only once, on a single machine, and the others take advantage of it.

  1. Choose the machine that hosts the model. Better a mini PC or a laptop with 16 GB and even a modest GPU: the GPU matters because inference is tied to memory bandwidth.
  2. Make it reachable from the other PCs. On macOS and Windows the setting is in the application options. On Linux, by default restricted to localhost, you must expose it explicitly: 
    sudo systemctl edit ollama

[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
    then sudo systemctl daemon-reload && sudo systemctl restart ollama.
  3. Open the port in the firewall only on the local network, never on the Internet: 
    sudo ufw allow from 192.168.1.0/24 to any port 11434
  4. Give the other PCs the address of the machine that hosts the model: if its IP is 192.168.1.50, the other programs will use http://192.168.1.50:11434/v1.

Never expose the port on the Internet

Ollama has no authentication: whoever reaches the port can use your model without limits and without you knowing. Exposing it on a public network or forwarding the port on the router is the easiest way to give free access to your GB of model to anyone who passes by. If you really need access from outside the house, put a reverse proxy with authentication in front, or use a tunnel with authentication.

Common problems

Four errors you run into almost always, with the real cause and the solution.

Error

"connection refused" on port 11434

The service is not running. On Linux: systemctl start ollama. If the problem persists even after startup, a firewall or an antivirus is blocking the port. On Windows, verify that Ollama is started from the icon in the status bar, not just installed.

Error

"not found, try pulling it first"

The requested model is not local. Check the available names with ollama list and in the official library; before downloading, verify the size, the quantization and the indicated size for the chosen tag.

Error

The model freezes or goes into swap

Compare free RAM, weight size, context cache and runtime requirements. Try a shorter context or a smaller model. VRAM can help only when the runtime, the drivers and the backend support the GPU; even with 8 GB it is not guaranteed that a 7B model fits entirely.

Error

The model is slow or does not use the GPU

Check with ollama ps whether the model is assigned to the CPU or the GPU; verify drivers, backend and card support in the documentation. There is no single expected speed: model, quantization, memory, context and cooling change the result.

Frequently asked questions

Which is better, Ollama or LM Studio?

It depends on how you want to use them. LM Studio offers a graphical interface for finding, downloading and managing models; Ollama is oriented toward the terminal, a local service and the API. RAM and compatibility depend on version, system, model and settings: check the requirements and measure the real usage on your PC.

Which of the two uses less RAM?

There is no fixed value valid for everyone: RAM usage depends on version, system, session and model. In Ollama you can check the active models with ollama ps and unload one with ollama stop nome-modello; in LM Studio check the settings of the installed version.

Does Ollama work without a graphical interface?

Ollama can be used from the terminal and started as a service without a desktop. For local requests the default API is on port 11434; access from the network requires additional configuration and must be limited to trusted devices.

How do I request a response from Ollama from a program?

Through its HTTP API on port 11434, which is also compatible with the OpenAI format. With curl: curl http://localhost:11434/api/chat -d '{"model":"qwen2.5:7b","messages":[{"role":"user","content":"Ciao"}],"stream":false}'. With stream true you receive the responses token by token. To serve another machine: OLLAMA_HOST=0.0.0.0:11434 ollama serve. In Python with the ollama library, or with any client that accepts an OpenAI base URL and points to http://localhost:11434/v1.

Can they be used together?

You can use both, but the path and the supported formats depend on the app and the model. Do not assume that a model downloaded in one is automatically importable in the other; check the documentation and watch the RAM if you keep them open together.

Does Ollama support NVIDIA cards?

Support depends on the GPU model, the operating system, the drivers and the backend available in the installed version. Consult the official documentation and check with ollama ps whether acceleration is used; the CPU can be available but the required instructions vary.

Which model do I download to start?

Choose the task first and check the RAM, context and runtime requirements on the model's page. An example tag is qwen2.5:7b, but it is not a universal recommendation; the catalog collects other examples.

How to choose between Ollama and LM Studio

LM Studio suits those who prefer a graphical interface for finding, downloading and managing models. Ollama offers a terminal workflow and a local API, useful for connecting programs or creating a service. Features, formats and requirements change with versions: consult the official documentation before installing or integrating a model.

Performance depends on the model, the quantization, the context, the CPU, the memory, the GPU and the backend. The size of the weights on disk does not match the RAM required; check the memory actually available during a test.

For Windows x64, LM Studio lists AVX2 among the requirements; the Linux x64 package includes AVX2 by default. Ollama uses different CPU runners and compatibility varies by build and backend. For CPUs without AVX2, verify the exact requirements before choosing a runtime.
